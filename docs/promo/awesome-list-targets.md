# Awesome-list submission targets

Search GitHub for `awesome-claude`, `awesome-anthropic`, `awesome-mac-menubar`,
`awesome-macos-apps`. Status as of this writing — verify each before PR'ing
(lists die / move):

| Target | URL | Section to add |
| --- | --- | --- |
| awesome-claude | https://github.com/taishi-i/awesome-ChatGPT-repositories (sometimes accepts Claude tools) | Tools |
| awesome-anthropic | https://github.com/raphaelmansuy/awesome-anthropic | Tools / Monitoring |

| awesome-macos-apps | https://github.com/iCHAIT/awesome-macOS | Menu Bar |

## PR boilerplate

```
- [claudegrain](https://github.com/FlyTOmeLight/claudegrain) — Granular Claude Code usage in your macOS menu bar. Per-repo / per-tool / per-MCP / cache-hit attribution. Native Swift, MIT.
```

Keep entries to one line per most awesome-list style guides. Don't oversell.

## Avoid

- Lists that haven't been updated in >12 months — the PR will sit forever.
- Lists with strict "must have ≥N stars" rules — wait until the repo qualifies.
- Lists where every entry is paid / sponsored — mismatch.

## After landing

Each accepted PR is a backlink + listing in any tool that scrapes the awesome
ecosystem (e.g. uneetcode.com, libhunt). Track in a spreadsheet so you don't
ask the same maintainer twice.
