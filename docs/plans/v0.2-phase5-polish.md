## 1. Audit findings

### 1.1 Animation
- `DetailPanel.swift:188` — `HeroSpend` `tab(...)` switches with `easeOut 0.18` but the cost number reanimates only via `.contentTransition(.numericText())` keyed on `costUSD`; mode switch (TOTAL ↔ TODAY) is instant for everything *except* the dollar value. Sub-label, model bar, yesterday-delta line all snap.
- `DetailPanel.swift:95` — `PauseBanner` appears/disappears with no transition. Layout shifts abruptly.
- `DetailPanel.swift:104` — `ForecastBadge` shows/hides on `forecastBlock?.basis != .insufficient` change with no transition.
- `DetailPanel.swift:544` — refresh spinner spin works, but the "F5 Refresh" button has no press/depress feedback (no `scaleEffect` on tap).
- `DetailPanel.swift:572` `kbd(...)` — same: no press feedback on F2/E/P/F10.
- `StatusItemController.swift:124` — `togglePopover` uses `popover.animates = true` (default fade), but the SwiftUI content inside doesn't transition on first show; first-paint feels jumpy when forecast/banner pop in.
- `MenuBarLabel.swift` — status dot color flips instantly between green/yellow/red. No crossfade.
- `CommitmentsSheet.swift:18` — list shows no transition when entries are added; sheet appears and the first row pops.
- Refresh state: `model.isRefreshing` floor-pads to 0.6 s (`DetailPanel.swift:564`), but the rest of the popover doesn't reflect "refreshing" — only the spinner glyph does. Cost number doesn't dim, vitals don't pulse.

### 1.2 Visual hierarchy
- Three font registries in play in `DetailPanel.swift`: `Font.cgMono*` tokens, raw `Font.custom("JetBrains Mono", size: 9.5)` (lines 290, 394, 401), and `Font.custom("JetBrains Mono", size: 13)` (line 429). Token discipline broken — fix to `Theme.swift:60–69`.
- Padding rhythm: `ReceiptScroll` uses `padding(.horizontal, 14)` + `vertical, 12` (`DetailPanel.swift:46–54`). `PauseBanner` uses `8 / 5` then outer `4` (`DetailPanel.swift:746–753`). `kbd` uses `6 / 2` (line 588). No 4 / 8 / 12 / 16 grid.
- `BudgetsTab.swift` has section header *inside* the `Section { } header: { }` form, but the global section uses string-init `Section("Global")`. Inconsistent.
- `QuietHoursTab.swift` uses unlabeled sections; `BudgetsTab.swift` uses labeled sections. SettingsView tabs feel like different authors.
- `aboutTab` (`DetailPanel.swift:679–698`) uses raw SwiftUI defaults (`.title2.weight(.semibold)`, `.callout`, `.caption`) — none of the V18 token system. Settings looks like a different app from the popover.
- `notificationsTab.snSound` Section header label is reused twice (line 665 and 666) — `Section(model.t(.snSound))` outer + `Picker(model.t(.snSound), …)` inner.

### 1.3 Empty states
- `DetailPanel.swift:236–246` `TopCostsList` — when `model.topRepos` is empty (cold start, fresh install), renders nothing. Should say "Watching jsonl for first activity…".
- `DetailPanel.swift:142` `WeekLineChart` — `weekPoints` synthesizes a fake ramp when `model.weekSpend.count != 7`, rendering an unlabeled fictional curve. Should be replaced by an explicit "no week data yet" placeholder, not fake bars.
- `BudgetsTab.swift:33–34` empty-text exists ("No per-repo budgets yet"), but lacks call to action (no "+ Add" hint).
- `CommitmentsSheet.swift:14` — empty state is just a grey one-liner; no explanation what a commitment is or when one appears.
- `Notifications` tab — no list of recent fired notifications, but also no empty state for the trigger toggles. Acceptable.
- `ModelMixRow` (visible in scroll mode only, `DetailPanel.swift:153`) — when `model.modelMix` is empty (cold start) it draws nothing. Silent gap.

### 1.4 Loading states
- `model.isRefreshing` only spins the F5 glyph (`DetailPanel.swift:529`). No global "refreshing" indicator.
- Bootstrap (`AppCoordinator.swift:127–130` `ingest.bootstrap(daysBack: 7)`) gives no UI signal during cold-start ingest. Popover shows zeros until first snapshot lands; user thinks app is broken.
- `dataSourceStatus == .unknown` (`AppModel.swift:104`, `HeaderStrip.statusLabel:220`) shows label `statusBoot` but the rest of the panel renders zero values without any "checking" treatment.
- OAuth `oauthBackoff` (`AppCoordinator.swift:238`) is intentionally invisible (keeps prior status). Good — but the *staleness* of the displayed snapshot is never surfaced. Add an "as of HH:MM" subtitle when not live.

### 1.5 Error states
- `DataSourceStatus.offline` (`AppModel.swift:109`) only sets the header label to `statusOffline`. No actionable banner ("Open Network Settings" / "Retry"). `AppDelegate.swift:60` sets it on coordinator init failure and never recovers — no retry.
- OAuth deprecation (`oauthDeprecated`, ADR-0004) collapses to `jsonlOnly` (`AppCoordinator.swift:236`). No user-facing notice that the OAuth path died — ADR-0004 explicitly anticipates this; UI should surface a one-line "Real-time quota disabled — using JSONL estimate" banner with a "Reauth" affordance.
- `LoginItemController.lastError` (`DetailPanel.swift:649`) is only displayed in the General tab as a red caption. No retry button.
- File watcher failure: there's no surfaced error path in UI. If FSEvents fails (e.g. permissions), popover silently shows stale data.
- JSONL parse errors are swallowed in `IngestActor` (per architecture). Polish: a footer "N events skipped" counter would let the user see something is wrong.

### 1.6 Keyboard shortcuts
- `DetailPanel.swift:443–449` — F2 / F5 / E / P / F10 are **labels only**. The buttons aren't bound to actual keys. Pressing F5 does nothing. Largest single polish miss in the build.
- No `keyboardShortcut(.init(",", modifiers: .command))` for Settings.
- No ESC binding to close the popover (popover is `.transient`, click-outside closes it, but ESC doesn't).
- No Cmd+R for refresh (industry idiom).
- No Cmd+W to close commitments/export sheets.
- `CommitmentsSheet.swift:40` and `ExportSheet.swift:119` correctly use `.cancelAction` — keep these.

### 1.7 Tooltips
- Two `.help(...)` calls in the entire app (`BudgetsTab.swift:121, 153`).
- F2/F5/E/P/F10 buttons in footer have **no tooltips** — first-time user has no idea what they do beyond the 1-3 char label.
- HeroSpend tabs (TOTAL / TODAY) — no tooltip explaining "all-time" vs "today".
- Vitals percentages — no tooltip explaining "session block = 5h rolling window" (the canonical term per CONTEXT.md).
- Status dot in menu bar (`MenuBarLabel.swift:13`) — no tooltip; users don't know what color means what.

### 1.8 Accessibility
- Zero `accessibilityLabel` / `accessibilityValue` annotations across `DetailPanel.swift`, `ReceiptComponents.swift`, `MenuBarLabel.swift`. VoiceOver reads the ASCII bar `"████░░░"` literally.
- `LiveDot` (`ReceiptComponents.swift:47`) and `MenuBarLabel.swift:13` status dots are unlabeled.
- ASCII art divider rows (`DoubleDivider`, `DashedDivider`, `StarsDivider`, `stencilTitle`) get read aloud as garbage. Mark as decorative.
- No `@Environment(\.accessibilityReduceMotion)` checks. `LiveDot` (`ReceiptComponents.swift:58`) pulses forever; refresh spinner spins continuously — both should freeze under Reduce Motion.
- Custom JetBrains Mono fonts at 7.5–11 pt aren't legible at default Dynamic Type and don't scale. App is `LSUIElement`, not document UI, so full Dynamic Type may be out of scope, but at minimum the popover should respect "Larger Text" preference for body copy.
- Phosphor mode `theme.ink.opacity(0.32)` (used in `DotLeader`, `StarsDivider`) on near-black background fails WCAG AA contrast.

### 1.9 Dark mode parity
- Phosphor (dark) and Thermal (light) are both bespoke (`Theme.swift:18–46`). Switching `colorScheme` triggers full repaint with no transition (`DetailPanel.swift:9`).
- `LoginItemController.lastError` red text (`DetailPanel.swift:650`) uses `.red` literal — wrong on Phosphor (clashes with `theme.crit`) and on Thermal (too saturated).
- `BudgetsTab.swift:115` accent `Color.accentColor` doesn't follow the V18 palette in the popover-themed widgets, but it's fine in Settings (which is system-themed).
- About tab (`DetailPanel.swift:679–698`) uses default `.secondary`/`.tertiary` — fine in Settings, but jarring if user expects a phosphor look.
- Glow effects (`neonGlow`) only applied when `theme.glowEnabled` — Thermal has it off. Good. But the green dot in `MenuBarLabel.swift:39` doesn't switch tone in light mode; it stays SwiftUI `.green` which is too saturated for Thermal/light menu bars.

### 1.10 Performance
- `DetailPanel.swift:225` — `HeaderStrip.timeString` rebuilds a `DateFormatter` every body recompute and clocks via the parent's redraw cycle. No timer; current time only updates when AppModel publishes. Time looks frozen between events.
- `StatusItemController.swift:67` `model.objectWillChange.sink` fires `updateButton()` on **every** AppModel publish (forecast, modelMix, weekDelta, refresh flag, …). Menu bar label re-renders far more often than it changes.
- `DotLeader` (`DetailPanel.swift:318`) recomputes per-row width via `GeometryReader` and concats a `String(repeating: " .", count: count)` on every layout pass.
- `ReceiptComponents.swift:58` `LiveDot` runs an unbounded `repeatForever` animation; cheap, but combined with refresh spinner it's two looping animations even when popover is closed (SwiftUI keeps animations alive while view exists).
- Popover open latency: `popover.contentViewController` is set once at attach (`StatusItemController.swift:47`), so reopen is fast. But the host view re-runs the SwiftUI body tree on every reopen — fine for now.
- `IngestActor` debounce tuning: not in scope unless we observe popover lag from publish storms. Leave as-is unless audit T13 finds it.

## 4. Animation guidelines

Single source of truth lives in `Motion.swift` (see P5-T09).

**Canonical timings** — pick one, never inline numbers:

| Token       | Duration | Curve                        | When to use |
| ----------- | -------- | ---------------------------- | ----------- |
| `.cgFast`   | 0.15 s   | `easeOut`                    | Tap feedback, tab indicator move, hover state |
| `.cgMedium` | 0.30 s   | `easeInOut`                  | Banner show/hide, cross-fade between modes, status dot color change |
| `.cgSlow`   | 0.50 s   | `easeInOut`                  | Page-level transitions (rare; use sparingly) |
| `.cgSpin`   | 0.70 s   | `linear`, `repeatForever`    | Refresh spinner |
| `.cgPulse`  | 0.70 s   | `easeInOut`, `repeatForever` | LiveDot, attention pulses |

**Rules**:
- Never inline `.easeInOut(duration: 0.42)` etc. If a new timing is needed, add a token.
- All looping animations gated through `Motion.preferred(...)` so Reduce Motion freezes them.
- Numeric values use `contentTransition(.numericText())` + `value:` keyed animation; never animate `String` length (causes type-out effects).
- Insertion/removal: `.transition(.opacity.combined(with: .move(edge: .top)))` for banners; `.transition(.opacity)` for in-place swaps.
- Popover open is owned by AppKit (`NSPopover.animates = true`); don't fight it with extra SwiftUI fade.

## 5. Out of scope

These look like polish and aren't:

- New Settings tabs (Themes picker, Sound packs, etc.) — feature, not polish.
- New metrics in popover (model-fan-out, time-to-first-token, etc.) — feature.
- New data sources (Anthropic console scrape, etc.) — would require ADR; not polish.
- Replacing JetBrains Mono / Space Mono — typography swap is identity change, not polish.
- Window-mode / dockable popover — major UX shift.
- iOS / iPadOS — out of milestone.
- Migrating to MenuBarExtra — already rejected (notch issues, see `StatusItemController.swift:5`).
- Localization beyond EN+ZH — separate phase.
- Phase 4 widget work — separate plan, parallel.
